✅ Storybook — обов'язковий етап

Для будь-якої задачі/лінки пайплайн один і той самий — Storybook не пропускається.

Єдиний потік spec → builder → reviewer → storybook → (твоє ОК) → shipper

storybook завжди дає локальний прев'ю + Chromatic-лінк і зупиняється на твоє ОК перед push.

Ролі та зони відповідальності

ОРКЕСТРАТОР

lead

Керує пайплайном, маршрутизує задачі, ставить питання, чекає ОК перед push.

Зона: координація, рішення, гілка Storybook так/ні.

1 · SPEC

spec

З ТЗ/Figma пише SPEC.md: екрани, стани, поведінка, edge cases, вимога Tailwind.

Зона: єдине джерело правди.

2 · BUILD

builder

Vite + React + TS суворо за SPEC. Чисто, просто. Стилі — Tailwind CSS.

Зона: реалізація коду.

3 · REVIEW

reviewer

Read-only: відповідність SPEC, усі стани, базова a11y, Tailwind → PASS/FAIL.

Зона: контроль якості (нічого не редагує).

4 · PREVIEW

storybook обов'язково

Story на кожен стан, лінк на Storybook + npx chromatic лінк. Зупиняється на ОК.

Зона: візуальний прев'ю компонента.

5 · SHIP

shipper

Після ОК: git commit + push у GitHub. Chromatic + Cloudflare деплоять самі.

Зона: Chromatic-лінк + live URL.
